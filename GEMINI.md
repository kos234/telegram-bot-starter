# Project Context: многомодульный стартер телеграмм бота

## 1. Обзор и цель проекта  
**Основная цель:** вынести общую логику обработки команд, кнопок, стейт машины и списков, чтобы повторно не реализовывать её в каждом боте .  
**Сфера деятельности:** телеграмм боты для магизинов и инфлюенсеров.     
**Целевая аудитория:** клиенты магазина, аудитория инфлюенсера и администраторы ботов.

## 2. Основные технологии и стек
**Языки:** Java 21
**Фреймворки и среды выполнения:** spring-boot-starter-parent 4.0.6, spring data jpa  
**Базы данных:** PostgreSQL, Redis  
**Ключевые библиотеки:** org.telegram.telegrambots-springboot-longpolling-starter:9.2.0, org.telegram.telegrambots-client:9.5.0, com.github.ben-manes.caffeine.caffeine:3.2.3, org.projectlombok.lombok:1.18.42  
**Менеджер пакетов:** Maven

## 3. Архитектурные паттерны
**Общая архитектура:** многомодульный стартер, с архитектурой вертикальных срезов, где срез один какой-то функциональный блок, в каждом срезе архитектура разбиения по слоям  
**Философия структуры каталогов:**
- `/telegram-bot-spring-boot-starter`: основной набор классов и методов для телеграмм ботов  
- `/telegram-bot-payment-tinkoff-spring-boot-starter`: модуль для внедрения оплаты т-банка  

## 4. Соглашения о кодировании и руководство по стилю
**Форматирование:** отступы, длина строк, руководства по стилю java  
**Соглашения об именовании:**
- Переменные: camelCase
- Классы: PascalCase
- Файлы: PascalCase
  
**Обработка ошибок:** логирование ошибки в логгер, показ сообщения пользователю, что произошла ошибка в обработчиках команд, кнопок и состояний

## 5. Особые указания по совместной работе с ИИ
**Запрещенные действия:**
- ❌ Никогда не изменяйте файлы .env
- ❌ Не устанавливайте зависимости без запроса
- ❌ Избегайте критических изменений в общедоступных API

**Обязательные правила:**
- ✅ Всегда добавляйте модульные тесты для новых функций
- ✅ Следуйте существующим шаблонам обработки ошибок
- ✅ Обновляйте документацию, Readme.md при внесении изменений в API
